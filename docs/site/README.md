# WorldCupArena site

Static single-page site deployed to GitHub Pages. Renders:

1. **Next match** — the upcoming fixture from `configs/fixtures.yaml` plus the
   per-model win probabilities, most-likely score, and reasoning excerpts.
2. **Leaderboard** — three views:
   - Composite (100-point rubric, ranked)
   - Per-layer radar chart (T1–T5 breakdown, Chart.js)
   - S2 − S1 uplift (research agent vs context-fed LLM, when both exist)
3. **History** — expandable cards for every graded fixture.

## Files

| File | Purpose |
|---|---|
| `index.html` | layout + Tailwind (CDN) |
| `app.js`     | fetches `data.json` and renders everything client-side |
| `data.en.json` / `data.zh.json` / `data.json` | generated by `python -m src.leaderboard.build_site` and ignored by git |

No Node toolchain. The only build step is regenerating the static JSON payload.

## Data flow

```
data/results/*/*.json  ─┐
data/predictions/*/*/  ─┼─►  src.leaderboard.build_site  ─►  docs/site/data.en.json
configs/fixtures.yaml  ─┘                                      docs/site/data.zh.json
                                                               docs/site/data.json
                                                                        │
                                                                        ▼
                                                             docs/site/index.html
                                                            (served via GitHub Pages)
```

## Updating the site locally

```bash
python -m src.leaderboard.build_site
python -m http.server -d docs/site 8000
open http://localhost:8000
```

To inspect the exact JSON currently served by GitHub Pages:

```bash
python -m src.leaderboard.fetch_deployed_site_data
```

That command refreshes the ignored local copies in `docs/site/`. It does not
change the source artifacts that the next local build uses.

To sync a local run to GitHub, commit the source artifacts, not the generated
site JSON:

```bash
git add configs/fixtures.yaml data/snapshots data/predictions data/results data/live data/search_logs data/i18n docs/leaderboard
git commit -m "update predictions"
git push
```

GitHub Pages then runs `python -m src.leaderboard.build_site` and publishes new
`data.en.json`, `data.zh.json`, and default `data.json` in the deployment
artifact.

## Production deploy

1. `.github/workflows/automate.yml` runs the pipeline, rebuilds the site
   payload as a validation step, and commits source artifacts/cache to main.
2. `.github/workflows/pages.yml` picks up source-data pushes, regenerates the
   bilingual JSON payload, and publishes `docs/site/` to GitHub Pages.

So each fixture's lifecycle visibly updates the public site twice:
once after lock+predict (T-24h, predictions appear), and once after grade
(T+3h–T+48h, leaderboard + history update).

Enable Pages in repo Settings → Pages → Source = "GitHub Actions".
